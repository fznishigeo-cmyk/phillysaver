# Phone home LCP — 2026-10-23

Status: **measured in real Chromium; fixed behind `keep_first_cards`** (strict bool,
code default false, config.yaml true). Branch `phone-lcp` from `9459a61`.

Operator figures (not remeasured here): Lighthouse mobile home LCP **6.88 s**, card
text as the LCP element, ~4.5 s after first paint; Get deal on **1.9%** of phone home
views vs **35.7%** on laptops.

## What happened on the page

- `drop-fresh-loader.js` loads the module after `requestAnimationFrame` + timeout;
  once inventory is in, `render()` assigns `content.innerHTML = html`, discarding the
  server's whole card wall even when it is the same cards in the same order.
- The server's cards drew a collapsed `<details class="how">` ("How to get this
  price: Promo code required"); the module draws an open box with the copy-code
  button. That open box, painted only by the module, was the largest text on the
  first screen, so LCP moved to the module's render (and the card grew under the
  thumb).
- The static wall uses the publication's drop mark; `dropPickIndex()` uses the
  visitor's clock. A publication from the previous 15-minute mark swapped every
  card for a different drop on first load.
- `engagement.js` `refreshSaved` → `repaintSaved` → `render()` re-rendered the same
  wall again on `pageshow` / tab return.

## The fix (`keep_first_cards`, dealradar/publish/keep_first_cards.py)

- A fresh-view render whose cards are the ones on screen, in the same order (server
  cards: same title, price and photo; page cards: same keys), patches the existing
  nodes into exactly the markup the replacement would have written
  (`keep-first-cards.js`, appended to `drop-fresh.js`). The first eight stay in
  their grid; the rest move into the grid after the Join band. Otherwise (a new
  drop, a search, another view) `innerHTML` replaces as before. The same patch
  covers the Saved repaint on `pageshow` / tab return.
- Stale mark: the smallest safe option is to keep the publication's drop, the one
  already on screen, until the clock's next mark, where the existing drop path
  takes over (the "N new deals just dropped" pill once the visitor has scrolled).
  Mixing the first eight of one drop with the rest of another would break the
  front mix, spacing and category-run rules at the seam; this keeps a whole drop
  those rules already produced. A new publication ends the hold.
- The home wall's static cards draw the module's How box (Python port with a
  node parity test, card_tidy on and off), so the module paints nothing new and
  larger on the first screen. Category/store pages keep their `<details>`. No-JS
  home visitors now see the same open box as everyone else.
- Bytes (phone fixture): home HTML gzip 74,148 → 74,156; pre-front-mix fixture
  76,348 → 76,345 (the ≥1,000-byte reserve test still holds). Off: every one of the
  1,411 published files byte-identical to `9459a61`; `pre_keep_first_cards` is
  chained into `pre_social_profiles`.
